# 接入地址、站点策略与 IP 统计

## 对外接入地址

服务设置中的公开访问 URL 是机器级配置，保存到 `data/service-settings.json`，切换账号不变。只允许部署机器操作保存；读取接入地址仍遵守当前账号白名单和管理鉴权。

- 显式填写的 HTTP(S) 地址按原协议、端口和路径使用；自动补一个 `/v1`。反向代理的 HTTPS 地址未写端口时使用标准端口，不拼接网关内部端口。
- 留空时优先使用浏览器访问的域名或 IP 及端口。通过 localhost 或 127.0.0.1 打开管理页时，仅在发现唯一可用局域网 IPv4 地址时自动推荐；多网卡或只有本机地址时提示手动配置。
- 自动模式使用正在运行的监听端口，保存但尚未重启的新端口不会提前出现在复制结果里。
- 每次点击复制重新读取配置，读取失败不会复制旧缓存。复制失败时显示此次读取的地址供手动复制。
- 重启后的管理页跳转基于当前管理地址，不使用可能指向另一域名的公开 API 地址。显式公开地址不会因监听端口修改而自动改写，直连场景需同步更新。

## 站点策略

站点编辑器只保留「连接信息」「模型与测试」「路由设置」。模型目录、目录刷新间隔、测试模型与一次性生成测试放在同一个页面。自动模型选择取上游列表第一项，不据此宣称免费或最便宜。

账号探测策略统一设置后台生成测试总开关和最小间隔。每个站点只选择是否参与以及使用哪个模型；界面显示当前组合是否生效。两级开关必须都开启，站点也必须启用且有模型，才可能执行后台测试。近期业务调用、限流、故障冷却和额度不可用等状态仍按调度器规则跳过或延后。手动测试是独立的一次操作，可能计费。

目录检查读取元数据，最短 300 秒；与生成测试间隔分别配置。账号故障重试控制一次业务请求失败后的站点切换和重试，不是后台测试任务。

### 健康度与调度

- 健康度以真实业务可靠性为基础，速度权重默认 15%，手动优先级不改变分数。在「站点管理 → 账号评分策略」设置 0–100%：0% 只看可靠性，100% 完整应用速度系数；可恢复默认值。各账号独立持久保存，保存后立即重算分数和调度，无需重启或重新积累样本。配置文件为 `gateway.scoring_speed_weight: 0.15`，账号设置优先。停用显示 0；没有近期有效样本显示「待评估」，少量样本使用中性色。点击分数可查看可靠性与实际速度影响。
- 每站保留最多 1,000 个带时间、模型和协议的结果；站点汇总及单模型协议评分各取最近 24 小时、最多 100 个有效结果。每过去 6 小时或向前 20 个样本，权重分别减半。样本使用 2 个成功率 90% 的先验作平滑：`100 × (加权成功数 + 1.8) / (权重总和 + 2)`。样本时效不因刷新界面或重启而延长。
- 流式业务正常结束才记健康成功，断流和上游显式错误记失败。客户端取消、参数错误、本地连接池等待超时、HTTP 429 及额度不足不计健康失败，原请求统计仍保留相应结果。手动与后台探测不增加业务评分样本。
- 综合分为 `可靠性 × (1 − w + w × 速度分 / 100)`，其中 `w` 是配置的速度权重，分数处于可靠性的 `(1−w)` 至 `100%` 之间；默认 `w=0.15` 时为 85%–100%。流式使用首个有效内容的等待时间：≤2 秒为 100 分，≥30 秒为 0 分；非流式完整响应使用 10–120 秒。中间按对数曲线平滑，每个成功结果先封顶再按近期权重平均，单次极端延迟不会无限拉低分数；使用 2 个速度分 50 的中性样本平滑。缺少对应速度样本时也用 50，不冒充满速。失败只影响可靠性，避免同时扣速度分。
- 实际路由先检查启停、额度、限流、熔断及模型协议支持，再比较请求对应的模型、协议综合分；速度样本还区分流式与非流式。未知组合使用中性调度值获得正常业务采样机会，不主动发起生成。健康分相差 5 分内按配置权重及手动偏好分流，不再额外按延迟降低权重。
- 手动优先级 1–5 在同健康度档位内分别给予 2 / 1.8 / 1.6 / 1.4 / 1.2 倍分流权重，6 及以上为 1 倍。首页排名仅为站点整体参考，不代表所有模型的固定顺序。
- 旧版评分布尔样本缺少时间和错误归因，升级时停止用于评分，由新业务结果逐步建立健康度；历史调用数、用量、请求日志与保护状态保留。无需迁移数据库，也不额外消耗生成 Token。

### 熔断与恢复

- 连续上游连接失败、超时或服务错误达到阈值时，网关暂时熔断站点；HTTP 429 的限流等待和余额不足的额度保护单独处理。
- 冷却结束后，站点获得一次真实业务请求的恢复机会，不受低健康分阻挡。同一站点仅允许一个恢复请求在途；流式请求正常结束后才确认恢复。失败重新冷却，取消或本地错误不会立刻反复试探。
- 「连接检查」只读取元数据，不会凭 `/models` 成功解除生成熔断或额度保护。「验证恢复」发送一次所选模型的生成请求，可能计费；Go 订阅继续使用正常编程请求验证。
- 本地连接池等待超时不属于上游故障，不扣站点评分或累计熔断次数。网关替换该连接池，旧池等待至少 60 秒（或更长的已配置读取超时）后关闭；停服时一并回收。
- 服务重启最多等待业务请求 10 秒，再取消未结束请求并清理连接、保存统计；长时间生成可能被中断。
- Windows 安装脚本将 NSSM 的控制台停止等待设为 30 秒，为上述收尾留出时间。

## 请求日志与 IP 用量

请求日志提供日期、IP、模型联合筛选，图表可切换请求次数或已上报 Token；「IP × 模型用量」列出请求数、失败数、Token 和上报覆盖率，按可用高度分页。

这些图表与明细只统计当前账号保留的最近 N 条日志，再应用筛选条件；N 可配置。删除留存数据后相关统计同步缩小。它们与用量分析中的长期日汇总口径不同。

缺失 Token 显示「未上报」，不当作零用量；明确上报的 0 计入覆盖率。旧记录没有 IP 时显示「未记录 IP」，不会猜测归属。Token 是上游响应中的 usage，不代表扣费金额。

流式响应结束时，将上游最终 usage 补回对应请求，再计入 IP × 模型统计；并发请求使用开始时间与路由编号共同定位，避免串到其他 IP。请求已超出留存范围时只更新长期汇总，不重新插入日志。旧版本只记入日汇总、未写入请求记录的 Token 无法可靠分摊，不进行历史补算。
